钉钉会话报告台——业务操作说明

一、第一次使用

1. 把压缩包完整解压到一个固定文件夹，不要在压缩包里直接运行。
2. 双击“01_首次使用.cmd”。
3. 保持黑色启动窗口打开，等待自动安装。
4. 浏览器出现钉钉授权页面后，登录需要读取聊天的钉钉账号。
5. 如果授权页要求选择组织，选择该账号已经加入的任意正常组织。这里只用于完成钉钉授权，不会在报告台中按组织筛选聊天。
6. 授权完成后，报告台会自动打开。

二、配置大模型

首次使用或更换模型时操作一次：

1. 打开页面中的“大模型配置与测试”。
2. 使用 DeepSeek 官方接口时填写：
   接口协议：OpenAI Responses API
   Base URL：https://api.deepseek.com
   模型名称：deepseek-flash
   API Key：填写自己的 DeepSeek 官方 Key
   请求超时：120 秒
   瞬时失败重试次数：1
   Temperature：0.1
   最大输出 Tokens：6000
   每批最大输入字符：8000
   每批最大消息数：3
3. “大模型分析要求”和“周报格式模板”可按业务需要修改。
4. 点击“保存配置”。
5. 点击“测试模型”。
6. 等待“接口连接、模型响应、结构化输出、本人识别”四项全部变为通过。

如果使用的是 OpenCode Go，改用对应的 OpenCode Key，并填写：
   接口协议：OpenAI-compatible Chat Completions
   Base URL：https://opencode.ai/zen/go/v1
   模型名称：deepseek-v4-flash
其余配置可保持以上数值。不要混用两家服务的 Key。

三、生成一次报告

1. 点击“刷新聊天列表”，等待刷新完成。
2. 搜索并勾选本次需要分析的正常单聊或群聊，可多选。
3. 设置开始时间和结束时间。结束时间本身不包含在报告范围内。
4. 按需设置消息类型、发送人、关键词、机器人、系统消息、撤回消息和闲聊筛选。如果希望尽可能不漏，勾选全部需要的消息类型，不填排除条件，并把闲聊过滤设为“关闭”。
5. 核对“报告本人”。生成张三的个人报告时填写“张三”，必须与钉钉消息中的发送人显示名一致。
6. 个人报告保持“AI 摘要只汇总报告本人”开启。这样其他成员自己的工作不会算到张三名下；其他人明确提到或分配给张三的事项仍可按消息证据进入分析。若要查看团队事项，可手动关闭该开关。
7. 设置报告标题、分组方式、关注章节和本次补充要求。系统会在后台核对消息依据，但报告不会展示聊天原文和出处。
8. 点击“预览范围”。预览只核对配置，不会生成报告。
9. 核对所选聊天、时间、报告本人和提示；如有提示，按页面要求确认。
10. 勾选明确确认。
11. 点击“确认并手动生成”。
12. 保持启动窗口和页面打开，等待“读取聊天、清洗核对、分析数据、生成报告”全部完成。
13. 在“最近报告”中分别查看或下载：
    （1）本周已完成事项
    （2）周报。包含本周工作和下周工作计划，只展示整理后的事项，不展示会话、发送人、时间、消息 ID、引用原文或全量消息清单。

四、以后日常使用

1. 双击“02_日常启动.cmd”。
2. 保持启动窗口打开。
3. 打开报告台后，从“生成一次报告”的第 1 步开始操作。
4. 报告不会自动生成；只有你确认范围并点击生成后才会执行。

五、需要重新登录钉钉

1. 关闭正在运行的报告台窗口。
2. 双击“03_重新登录钉钉.cmd”。
3. 按浏览器提示重新授权。
4. 完成后再双击“02_日常启动.cmd”。

六、只想先试用

双击“04_演示模式.cmd”。演示模式使用示例聊天，不读取真实钉钉消息。

七、常见情况

1. 双击后闪退：不要直接运行 .ps1 文件，只双击四个 .cmd 文件。失败时窗口会保留，请截图完整提示。
2. 模型测试 HTTP 400：优先核对接口协议、Base URL 和模型名称。OpenCode Go 的 DeepSeek V4 Flash 使用 Chat Completions，不要选 Responses API。模型四项测试已经通过后，正式生成中偶发的 400 会自动有限重试并按需拆小批次；若单条仍失败，任务会停止并显示错误，不会跳过消息。
3. 修改模型配置后不能生成：重新点击“保存配置”和“测试模型”。
4. 找不到聊天：先点击“刷新聊天列表”；仍找不到时，可在高级项填写该聊天的 openConversationId。
5. 任务时间较长：一周消息较多时会自动分批。已经完成的批次会保存进度，中断后可继续使用，不会把未处理消息当作成功。
6. 页面打不开：确认启动窗口仍在运行，然后访问 http://127.0.0.1:8765。
7. 停止使用：关闭启动窗口即可。
8. 为什么报告里没有消息原文和出处：这是当前固定的业务展示方式。系统仍在后台用消息 ID 和逐字原文校验结论，但下载的两份报告只保留整理结果。
9. 提示找不到报告本人：先确认“报告本人”与钉钉发送人显示名完全一致，再检查所选会话和时间内是否确实有本人发送的消息或其他人明确提到本人。系统不会在身份无法核对时用他人消息凑报告。
10. DeepSeek 官方接口提示“没有返回有效 JSON”：先确认使用 1.3.8 或更新版本。新版已修复官方接口思考文本混入最终结果的问题，保存配置后重新测试即可。官方 deepseek-flash 和 deepseek-v4-pro 均已测试 Responses 和 Chat Completions 两种协议。
11. 提示“模型输出被截断”：增加“最大输出 Tokens”，例如从 6000 调整为 12000，保存并重新测试。生成时若消息较多，也可减小每批最大消息数。
12. 正式生成提示“模型 JSON 不符合证据候选结构”：确认使用 1.3.9 或更新版本。1.3.9 已修复同一条消息有多段内部证据时被误判的问题。升级时复制旧版整个 data 文件夹，可以继续复用已验证的成功批次；然后保存配置、重新测试模型，再用原范围生成。
